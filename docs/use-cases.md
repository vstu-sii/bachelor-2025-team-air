# 🧩 Use Cases — Система подбора персонала с ИИ

---

## **Use Case 1. Загрузка и анализ вакансии с резюме**

| Поле | Описание |
|------|-----------|
| **Описание** | Система анализирует загруженные HR вакансии и резюме кандидатов, формируя рейтинг соответствия и персональные вопросы. |
| **Акторы** | HR-менеджер |
| **Начальное состояние** | HR вошёл в систему и открыл интерфейс подбора персонала. |
| **Триггеры** | Нажатие кнопки «Загрузить вакансию и резюме». |
| **Успешный сценарий** | 1. HR загружает описание вакансии.<br>2. Загружает резюме кандидатов.<br>3. Система анализирует соответствие.<br>4. Формируется рейтинг (0–100%).<br>5. Для топ-5 кандидатов создаются персональные вопросы.<br>6. HR просматривает результаты. |
| **Альтернативный сценарий** | Система выявляет неполные данные в файле и предлагает их дополнить (см. UC2). |
| **Негативный сценарий** | Сбой при анализе данных или загрузке файла неподдерживаемого формата (см. UC5). |
| **Конечное состояние** | Сформирован отчёт с рейтингами и вопросами. |
| **Критерии приёмки** | HR открывает ≥2 профиля из топ-5 и приглашает кандидатов на собеседование в течение 10 минут. |
| **Связанные требования** | REQ-1: Поддержка форматов PDF, DOCX<br>REQ-2: Генерация рейтинга соответствия<br>REQ-3: Вывод отчёта в UI |

## **Use Case 2. Обработка неполных данных в резюме**

| Поле | Описание |
|------|-----------|
| **Описание** | Система проверяет резюме и вакансии на наличие обязательных полей и уведомляет о недостающих данных. |
| **Акторы** | HR-менеджер, Кандидат |
| **Начальное состояние** | Пользователь пытается загрузить резюме или вакансию. |
| **Триггеры** | Обнаружение пропущенных обязательных полей (опыт, образование, навыки). |
| **Успешный сценарий** | 1. Система валидирует данные.<br>2. Отображает сообщение об ошибках и недостающих полях.<br>3. Предлагает рекомендации по исправлению.<br>4. Пользователь исправляет данные и повторно отправляет. |
| **Альтернативный сценарий** | HR выбирает «Продолжить с предупреждением». Система анализирует с пониженной точностью. |
| **Негативный сценарий** | Пользователь не исправляет данные — анализ невозможен. |
| **Конечное состояние** | Резюме успешно обработано или отклонено. |
| **Критерии приёмки** | Пользователь исправляет данные с первой попытки, система успешно анализирует обновлённую информацию. |
| **Связанные требования** | REQ-4: Проверка структуры резюме<br>REQ-5: Сообщения об ошибках и рекомендациях |

## **Use Case 3. Работа с частично подходящими кандидатами**

| Поле | Описание |
|------|-----------|
| **Описание** | Система анализирует кандидатов, соответствующих вакансии частично (50–70%), и предлагает развитие навыков. |
| **Акторы** | HR-менеджер |
| **Начальное состояние** | Завершён анализ соответствия резюме вакансии. |
| **Триггеры** | Обнаружение кандидатов с рейтингом < 70%. |
| **Успешный сценарий** | 1. Система определяет пробелы в навыках.<br>2. Генерирует рекомендации по обучению или испытательному сроку.<br>3. Создаёт дополнительные вопросы.<br>4. Сравнивает с успешными кейсами. |
| **Альтернативный сценарий** | HR отмечает кандидата как «потенциально интересного» без добавления в список собеседований. |
| **Негативный сценарий** | HR игнорирует кандидата, система не сохраняет рекомендации. |
| **Конечное состояние** | Кандидат добавлен в список собеседований с пометкой «требует развития». |
| **Критерии приёмки** | HR добавляет ≥1 частично подходящего кандидата в список. |
| **Связанные требования** | REQ-6: Модуль анализа пробелов<br>REQ-7: Генерация рекомендаций по развитию |

## **Use Case 4. Генерация персонализированных вопросов для интервью**

| Поле | Описание |
|------|-----------|
| **Описание** | Система создаёт набор вопросов для интервью на основе опыта кандидата и требований вакансии. |
| **Акторы** | HR-менеджер |
| **Начальное состояние** | Анализ профиля кандидата завершён. |
| **Триггеры** | Нажатие кнопки «Сгенерировать вопросы». |
| **Успешный сценарий** | 1. Система анализирует опыт и навыки.<br>2. Формирует 5–7 персональных вопросов.<br>3. Добавляет 3–5 технических и поведенческих вопросов.<br>4. Отображает список HR. |
| **Альтернативный сценарий** | HR корректирует требования вручную перед генерацией. |
| **Негативный сценарий** | Ошибка генерации (недостаточно данных в профиле). |
| **Конечное состояние** | Список персонализированных вопросов доступен HR. |
| **Критерии приёмки** | HR использует ≥3 вопроса на собеседовании и отмечает их релевантными. |
| **Связанные требования** | REQ-8: Генерация вопросов<br>REQ-9: Категоризация вопросов (hard/soft skills) |

## **Use Case 5. Обработка технических сбоев и неподдерживаемых форматов**

| Поле | Описание |
|------|-----------|
| **Описание** | Система обрабатывает ошибки, связанные с форматами файлов или техническими сбоями. |
| **Акторы** | HR-менеджер, Кандидат, Система |
| **Начальное состояние** | Пользователь загружает файл или вызывает анализ. |
| **Триггеры** | Загрузка неподдерживаемого формата или сбой AI-модуля. |
| **Успешный сценарий** | 1. Система уведомляет о проблеме.<br>2. Отображает список поддерживаемых форматов.<br>3. Предлагает инструкцию по конвертации.<br>4. Регистрирует ошибку в техподдержке. |
| **Альтернативный сценарий** | Система автоматически конвертирует файл (если возможно). |
| **Негативный сценарий** | Сервис недоступен, пользователь не получает уведомление. |
| **Конечное состояние** | Ошибка зарегистрирована, пользователь уведомлён. |
| **Критерии приёмки** | Пользователь повторно загружает файл или получает уведомление о восстановлении сервиса ≤15 минут. |
| **Связанные требования** | REQ-10: Обработка ошибок<br>REQ-11: Поддержка форматов<br>REQ-12: Логирование событий |
